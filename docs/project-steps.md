## 总体开发目标

把当前 MVP 扩展为一个面向普通求职者的自动简历投递辅助系统。系统负责收集用户画像、解析简历、发现岗位、评分推荐、生成投递材料、记录投递状态，并逐步支持官网自动填表和招聘平台搜索辅助。

核心原则：

- 先做可控 MVP，再逐步自动化。
- 招聘平台投递前保留人工确认。
- 公司官网表单优先自动化。
- 简历和岗位数据要可追踪、可复盘、可导出。

## 阶段 1：MVP 稳定化

目标：让当前前端原型成为可演示、可测试、不会误导用户的版本。

任务：

- 保留示例岗位数据，并明确标注“演示样例”。
- 完善用户画像表单字段。
- 增加表单校验，例如城市、目标岗位、薪资范围不能为空。
- 增加空状态、加载状态、错误状态。
- 增加用户画像预览区。
- 将模拟岗位数据从页面代码中拆到单独数据文件。

交付物：

- 可运行的前端 Demo。
- 用户画像字段清单。
- 岗位推荐展示页。

验收标准：

- `npm.cmd run build` 成功。
- 用户可以完整填写资料并看到岗位匹配结果。
- 页面不会暗示已经连接真实 Boss 或 LinkedIn。

## 阶段 2：后端与数据库

目标：从纯前端 Demo 变成可保存数据的系统。

当前进度：基础版本已完成。

推荐技术：

- 后端：FastAPI 或 NestJS。
- 数据库：开发期 SQLite，正式部署 PostgreSQL。
- 文件存储：本地 uploads 目录，正式部署可换对象存储。

任务：

- 搭建 API 服务。已完成。
- 增加用户表、简历表、偏好表、岗位表、匹配表、投递记录表。已完成。
- 实现简历上传 API。已完成基础版，当前记录文件名，下一阶段处理真实文件内容。
- 实现用户画像保存 API。已完成。
- 实现岗位列表 API。已完成。
- 实现投递状态更新 API。已完成。
- 前端从 API 读取和保存数据。已完成。

交付物：

- 后端服务。
- 数据库 schema。
- 基础 CRUD API。
- 前后端联调完成。

验收标准：

- 刷新页面后，用户画像和投递状态不丢失。
- 上传的简历文件可以在后端记录。
- 岗位数据可以从数据库读取。

## 阶段 3：简历解析

目标：让系统从用户简历中自动提取求职画像，减少用户手动填写成本。

当前进度：PDF 基础解析已完成。

任务：

- 解析 PDF 和 Word 文档。已完成 PDF，Word 待接入。
- 提取姓名、学校、专业、学历、毕业时间。已完成基础规则抽取，后续增强字段结构化。
- 提取技能关键词，例如 Python、SQL、机器学习、深度学习、PyTorch。已完成基础关键词抽取。
- 提取项目经历、实习经历、比赛、证书、语言能力。已完成经历线索和语言基础抽取。
- 把解析结果存入 `parsed_profile_json`。已完成。
- 在前端展示解析结果，并允许用户手动修正。已完成展示，手动修正待接入。

当前示例：

- 使用根目录中的 `香港城市大学-商业人工智能-郑涵亓-简历.pdf` 做第一份解析测试样本。

交付物：

- 简历解析 API。
- 简历解析结果页面。
- 用户可编辑的解析字段。

验收标准：

- 系统能从 PDF 中抽取主要文本。
- 至少能识别教育背景、技能、项目/经历三类信息。
- 用户可以修正解析错误并保存。

## 阶段 4：岗位导入与真实岗位池

目标：开始接入真实岗位，但先不做全自动平台投递。

当前进度：手动导入真实岗位 JD/链接、搜索任务和解析预览已完成。

优先顺序：

1. 手动粘贴岗位 JD。
2. 手动导入岗位链接。
3. 公司官网 Careers 页面搜索。
4. Boss 和 LinkedIn 浏览器辅助搜索。

任务：

- 增加“导入岗位”页面。已完成。
- 支持粘贴 JD 文本并解析岗位信息。已完成基础规则解析。
- 支持保存岗位 URL。已完成。
- 支持导入前解析预览。已完成。
- 支持公司官网 Careers 页面搜索入口。已完成。
- 对 Boss 和 LinkedIn 先做搜索辅助，不绕过登录和平台限制。已完成基础搜索任务生成。
- 增加岗位去重逻辑。已完成链接去重，以及标题 + 公司 + 城市去重。

交付物：

- 真实岗位导入功能。
- 岗位详情解析功能。
- 岗位来源与更新时间记录。

验收标准：

- 用户能导入真实岗位。
- 系统能展示真实岗位和示例岗位的区别。
- 同一岗位不会重复进入岗位池。

## 阶段 5：匹配评分升级

目标：从简单关键词匹配升级为更可信的岗位推荐。

当前进度：前端规则型评分已完成，后续可保存到 `matches` 表。

评分维度：

- 岗位方向匹配。
- 技能关键词匹配。
- 城市和远程匹配。
- 求职目标匹配。
- 行业和公司类型匹配。
- 薪资范围匹配。
- 学历、年限、语言等硬性条件匹配。
- 简历项目证据匹配。

任务：

- 为每个评分维度设置权重。
- 输出匹配理由。
- 输出风险项和缺口。
- 支持用户调整偏好权重。
- 支持按匹配分、薪资、城市、来源排序。

交付物：

- 匹配评分服务。
- 匹配理由展示。
- 风险项展示。

验收标准：

- 每个推荐岗位都有分数、推荐理由和风险提示。
- 用户能理解为什么系统推荐或不推荐这个岗位。

## 阶段 6：材料生成

目标：根据岗位 JD 生成个性化投递材料。

第一版不一定需要大模型，先做模板化生成。后续再接 OpenAI 或其他模型。

当前进度：模板型材料生成已完成。

任务：

- 根据岗位生成简历微调建议。
- 标出应强化的技能关键词。
- 生成求职信草稿。
- 生成投递邮件正文。
- 保存材料版本。
- 支持用户编辑材料。

交付物：

- 材料生成页面。
- 简历微调建议。
- 求职信和邮件模板。
- 材料版本记录。

验收标准：

- 用户能针对一个岗位生成一份材料草稿。
- 材料能保存、编辑、复用。
- 系统不会自动篡改原始简历文件。

## 阶段 7：投递管理与提醒

目标：让系统成为求职 CRM。

任务：

- 增加投递看板。
- 状态包括：待确认、已加入队列、已投递、笔试、面试、拒绝、Offer、不合适。
- 增加备注。
- 增加跟进提醒。
- 增加统计面板：本周投递数、回复率、岗位来源分布、城市分布。

交付物：

- 投递 Kanban 或表格视图。
- 跟进提醒。
- 投递统计。

验收标准：

- 用户能追踪每个岗位的完整状态。
- 系统能提醒用户跟进长时间无反馈的岗位。

## 阶段 8：官网自动填表

目标：优先支持公司官网投递表单的自动填写。

任务：

- 识别官网表单字段。
- 自动填写姓名、邮箱、电话、学校、学历、工作城市、简历附件。
- 提交前展示确认页。
- 记录投递结果。

限制：

- 不自动绕过验证码。
- 不自动提交用户未确认的申请。
- 不批量轰炸式投递。

交付物：

- 官网自动填表模块。
- 表单字段映射。
- 提交前确认流程。

验收标准：

- 对常见 Careers 表单可以完成预填。
- 用户确认后才提交。
- 投递记录自动写入数据库。

## 阶段 9：Boss 和 LinkedIn 辅助搜索

目标：辅助用户发现岗位，而不是强行全自动批量投递。

Boss 直聘：

- 打开搜索页。
- 根据用户关键词、城市、岗位目标生成搜索条件。
- 辅助读取岗位标题、公司、地点、薪资、JD。
- 用户确认后加入岗位池。

LinkedIn：

- 打开职位搜索页。
- 根据关键词、地点、职位类型生成搜索条件。
- 读取公开可见岗位信息。
- Easy Apply 仅做预填和确认，不默认提交。

交付物：

- 平台搜索辅助模块。
- 登录态浏览器辅助流程。
- 岗位导入队列。

验收标准：

- 系统可以帮助用户找到真实岗位。
- 用户可以确认哪些岗位进入系统。
- 不进行未经确认的自动投递。

## 阶段 10：服务器部署

目标：让系统可以在服务器长期运行。

任务：

- 前端构建并部署。
- 后端服务部署。
- PostgreSQL 部署。
- 文件上传目录或对象存储配置。
- 环境变量配置。
- 登录和权限控制。
- HTTPS 和反向代理。

交付物：

- 线上可访问版本。
- 数据库和文件存储。
- 部署文档。

验收标准：

- 用户可以通过网页访问系统。
- 数据持久化。
- 基础权限和文件安全可控。
