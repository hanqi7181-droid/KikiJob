# KikiJob 新用户主流程说明

这份文档用于录屏讲解、冒烟测试和给新用户解释完整体验。描述的是当前系统主流程：登录注册、上传简历、填写资料、智能推荐、收藏岗位、辅助投递、投递记录和我的资料。

## 二、登录 / 注册体验

新用户打开系统后，会先进入 6 步引导的第 1 步“登录”。登录卡片提供两种方式：邮箱密码、邮箱验证码。

无论选择哪种登录方式，用户都必须先勾选“我已阅读并同意服务条款和隐私说明”。这段说明里会提示：登录后，用户的简历、字段词库、投递记录会按账号隔离保存。

邮箱密码登录：

- 用户输入电子邮件和密码。
- 未勾选协议时，提示“请先勾选同意服务条款和隐私说明。”
- 未输入邮箱时，提示“请先输入邮箱。”
- 未输入密码时，提示“请先输入密码。”
- 登录中按钮显示“登录中...”，状态提示“正在登录...”
- 成功后提示“登录成功，正在进入上传简历。”
- 失败时提示后端错误，或“登录失败，请检查账号密码。”

邮箱验证码登录：

- 用户输入邮箱，先点击“获取验证码”。
- 未勾选协议时，提示“请先勾选同意服务条款和隐私说明，再获取验证码。”
- 邮箱为空时，提示“请先输入邮箱。”
- 邮箱格式不正确时，提示“请输入有效邮箱后再获取验证码。”
- 发送中按钮显示“发送中...”，状态提示“正在向邮箱发送验证码...”
- 正式环境发送成功后提示“验证码已发送至 xxx@xxx.com”。
- 本地开发模式可能显示“邮箱验证码已生成：xxxxxx（本地开发模式）”。
- 用户输入 6 位验证码后点击“验证码登录”。
- 未输入验证码时，提示“请先输入邮箱验证码。”
- 验证中按钮显示“验证中...”，状态提示“正在验证...”
- 成功后提示“登录成功，正在进入上传简历。”
- 验证码错误或过期时，提示“验证码不正确或已过期。”

## 三、6 步新用户引导

整个引导共有 6 步：登录、上传简历、确认基本资料、设置求职偏好、自动填写设置、完成检查。

左侧有“资料气泡池”。用户每填写一项资料，左侧会动态出现气泡，例如姓名、学校、专业、学历、简历、意向岗位、意向城市、招聘类型、公司偏好、行业、技能、教育经历、工作/实习经历、项目经历等。左侧还会显示已收集数量、经历数量、当前步骤进度。用户可以直观看到系统已经收集到了哪些信息。

第 2 步“上传简历”：

- 支持选择 PDF、DOCX、TXT、Markdown。
- 上传后显示文件名、文件大小和状态。
- 状态包括等待上传、正在上传、正在解析、解析成功、上传或解析失败。
- 普通文本层 PDF 会由后端提取文本，再交给 Doubao 做结构化字段提取。
- Doubao 只能根据简历原文提取字段，不做总结、润色、推断或编造。
- 结构化结果会经过 Zod 校验。
- 解析出的内容只用于填写空字段，不覆盖用户已经手工编辑过的字段。
- 如果没有从文件中提取到可用文本，会提示可能是扫描版 PDF，当前暂不做 OCR。
- 如果 AI 解析不完整，系统会尽量用本地规则补充可识别字段，用户仍然可以继续手动填写。
- 用户可以查看“解析结果预览”，点击“应用解析结果”。
- 用户也可以删除当前引导草稿中的简历版本，或重新选择文件重试。

第 3 步“确认基本资料”：

- 用户确认姓名、邮箱、电话、学校、学历、专业、毕业时间。
- 必填校验包括姓名、邮箱、手机号。
- 下面可以继续编辑教育经历、工作/实习经历、项目经历。
- 简历识别出来的多段经历会以列表方式展示，用户可以补充、修改或删除。

第 4 步“设置求职偏好”：

- 岗位偏好按行业分组，先选行业，再选具体岗位。
- 当前行业包括人工智能、互联网、金融科技、咨询与商业分析、消费品与品牌、企业服务。
- 城市选择上方有常用城市：北京、上海、广州、深圳。
- 也可以按照 A-Z 字母分组搜索和选择中国省市。
- 招聘类型支持校招、实习、社招。
- 公司类型支持央国企、大厂、外企。
- 还可以填写届别/毕业时间、期望薪资、公司规模，并选择是否接受远程或混合办公。

第 5 步“自动填写设置”：

- 用户选择默认允许自动填写的资料类型：联系方式、教育经历、经历、项目经历。
- 薪资、到岗时间、签证/工作许可默认每次确认后再填。
- 性别、民族、残障、政治面貌等敏感字段默认不填，也不从简历推断。
- 密码、验证码、最终提交按钮永不读取、不绕过、不点击。
- 用户可以标记 Chrome Autofill 插件状态：稍后设置、已安装、需要安装说明。

第 6 步“完成检查”：

- 系统汇总简历与资料、岗位偏好、自动填写策略。
- 用户确认无误后点击“进入 KikiJob”。
- 进入后会来到 KikiJob 主工作台。

## 四、主页和智能推荐

进入主页后，系统会展示求职工作台：推荐、辅助投递、投递记录、我的资料等主功能。

用户点击“智能推荐”后，系统才开始生成推荐，不会一开始就把岗位全部塞到前端。当前是零预算轻量版推荐逻辑：

- 后端读取用户的公司类型、岗位偏好、城市偏好、招聘类型。
- 后端岗位池和官网入口池里的公司、岗位都带有标签，例如央国企、大厂、外企、银行、互联网、女性友好、AI、产品、数据、城市、校招、实习等。
- 系统按标签匹配度给候选岗位排序。
- 能匹配到具体官网岗位入口的，会放到“推荐岗位”栏。
- 不能稳定拿到具体岗位详情、但适合继续搜索的，会生成平台搜索入口，放到“搜索推荐”栏。
- 搜索推荐按钮叫“跳转搜索”，不会写“官方投递”。
- 官网岗位入口按钮叫“官方投递”。
- 推荐出来的岗位默认只是“待确认”，不会自动进入收藏，也不会自动进入投递记录。

推荐结果区域分为两个栏：

- 推荐岗位：具体公司官网、校招官网、实习官网或岗位入口，适合直接进入官方投递流程。
- 搜索推荐：牛客、实习僧、应届生、BOSS、拉勾、前程无忧等平台搜索入口，适合用户打开后按平台实时岗位继续筛选。

用户看到想投的岗位，可以点击卡片右上角爱心收藏。收藏后岗位进入“我的收藏”，状态变为“收藏/待投”。取消爱心后回到“待确认”，不会删除岗位池记录。

## 五、辅助投递和 Chrome 插件流程

用户决定投递某个岗位后，进入“辅助投递”。辅助投递是 8 步流程：选择岗位/链接、登录官网、确认申请页、创建 Session、扫描映射、扩展填充、人工提交、结果回写。

第 1 步选择岗位或链接：

- 用户可以从已保存岗位里选择一个岗位。
- 也可以不绑定岗位，直接粘贴官方投递链接。
- 系统会把这个岗位链接作为本次辅助投递目标。

第 2 步登录官网：

- 用户点击“打开招聘官网”。
- 招聘官网会在浏览器新标签页打开。
- 用户自己完成官网登录、短信验证、邮箱验证、验证码、人机验证等。
- KikiJob 不保存招聘网站密码、Cookie 或验证码。

第 3 步确认正式申请表链接：

- 用户登录后进入真正的申请表页面。
- 把当前浏览器地址栏里的申请页 URL 粘贴回 KikiJob。
- 如果当前页不是正式申请表，扫描结果可能很少或无法匹配。
- 如果登录过期，需要回官网重新登录。

第 4 步创建 Autofill Session：

- Session 只保存本次任务状态和字段结果。
- Session 不保存招聘网站登录态。
- 创建后优先用 Chrome 插件扫描真实页面。

第 5 步扫描字段并映射资料：

- 用户在招聘申请页打开 Chrome 插件，点击“扫描当前页”。
- 插件识别当前页面所有可填字段。
- 插件会尽量避免把“请输入”这类 placeholder 当成真实字段名。
- 对工作经历、教育经历、项目经历这类大块表单，插件会结合区块上下文做组合匹配，减少串填。
- 用户把扫描 JSON 复制回 KikiJob。
- KikiJob 把官网字段和用户自己的简历资料、字段词库、标准映射进行匹配。
- 页面会显示检测字段数、已匹配数、待确认数、未支持数。
- 用户可以逐项修改字段匹配和值。

第 6 步扩展填充：

- 用户确认字段后，KikiJob 生成填充包。
- 用户点击“复制扩展填充包”。
- 回到招聘申请页，在 Chrome 插件里粘贴填充包。
- 点击插件的“填当前页”。
- 插件只填字段，不点击下一步、不点击保存提交、不点击最终提交。
- 中低置信字段、敏感字段、文件上传字段，需要用户手动确认或手动处理。

第 7 步人工提交：

- 用户回到招聘官网逐项检查。
- 没填上的字段由用户自己补充。
- 简历附件、作品集附件等文件上传由用户自己完成。
- 确认无误后，最终提交按钮由用户自己点击。
- 系统提供三个结果选择：我已成功提交、无法确认结果、提交失败/暂不提交。

第 8 步结果回写：

- 如果用户选择“我已成功提交”，岗位状态回写为“已投递”。
- 如果选择“无法确认结果”，岗位状态回写为“结果未知”。
- 如果选择“提交失败/暂不提交”，岗位状态回写为“未通过”。
- 记录会进入投递记录，后续可以继续维护。

## 六、Chrome 插件安装教程

插件用于控制用户当前已经打开、已经登录的招聘申请标签页。普通网页不能跨域控制招聘官网，所以真实填表需要浏览器扩展配合。

安装步骤：

1. 打开 Chrome 或 Edge 的扩展管理页。
2. Chrome 地址是 `chrome://extensions/`，Edge 地址是 `edge://extensions/`。
3. 打开“开发人员模式”。
4. 点击“加载已解压的扩展”。
5. 选择项目目录下的 `chrome-extension/` 文件夹。
6. 工具栏出现 `Auto CV Autofill` 扩展后，说明安装成功。
7. 每次代码更新后，需要在扩展管理页点击重新加载扩展。

使用步骤：

1. 在招聘官网打开正式申请表页面，并完成登录。
2. 点击浏览器工具栏里的 `Auto CV Autofill`。
3. 先点“扫描当前页”，把扫描 JSON 复制回 KikiJob。
4. 在 KikiJob 里确认字段匹配并生成填充包。
5. 复制填充包，回到插件里粘贴。
6. 点击“填当前页”。
7. 用户自己检查页面、补齐字段、上传附件、最终提交。

## 七、投递记录

投递记录用于追踪用户真正关心或已经操作过的岗位。推荐结果本身不会自动成为投递记录；用户收藏、辅助投递或更新状态后，才会进入记录。

用户可以在投递记录里查看列表或看板，搜索筛选岗位，编辑备注、下一步行动、跟进时间，也可以修改岗位当前阶段。

当前阶段包括：

- 收藏/待投
- 准备材料
- 填表中
- 已投递
- 笔试
- 一面
- 二面
- 终面
- Offer
- 未通过
- 已撤回
- 结果未知

系统会根据阶段给出下一步提示，例如收藏/待投提示确认是否投递，准备材料提示完善材料，填表中提示检查官网表单，结果未知提示人工确认投递结果。

如果同公司同岗位或同投递链接重复出现，投递记录里会提示可能重复。删除一条投递记录时，不会真正抹掉所有信息，而是把状态改成“已撤回”，并允许用户立即撤销。

## 八、我的资料

“我的资料”是用户自己的数据中心，主要包括：

- 基本资料：姓名、邮箱、电话、学校、学历、专业、毕业时间等。
- 经历资料：教育经历、工作/实习经历、项目经历、技能。
- 简历版本：用户上传过的简历和解析结果。
- 求职偏好：岗位、行业、城市、招聘类型、公司类型、薪资、远程偏好等。
- 自动填写规则：哪些类型字段允许默认填写，哪些需要每次确认，哪些永不填写。
- 字段词库：用户在插件里修正过的网站字段映射，会按当前账号隔离保存。
- 隐私与数据：说明密码、验证码不读取，最终提交由用户自己点击。

用户可以在这里退出登录。退出登录只会清除当前浏览器里的登录状态，并回到 6 步引导；不会删除账号数据。用户下次用同一个账号登录后，简历、字段词库、投递记录仍然按账号读取。

## 九、冒烟测试用例

1. 新用户打开系统，应看到 6 步引导，从“登录”开始。
2. 不勾选协议直接登录，应提示先同意服务条款和隐私说明。
3. 邮箱密码登录：空邮箱、空密码、错误密码、成功登录都应有明确提示。
4. 邮箱验证码登录：未勾选协议、空邮箱、邮箱格式错误、发送成功、空验证码、验证码错误或过期、验证成功都应有明确提示。
5. 上传普通文本层 PDF，应显示上传中、解析中、解析成功，并预填可识别字段。
6. 上传扫描版 PDF 或无法提取文本的文件，应提示未提取到可用文本，用户仍可手动填写。
7. 在确认基本资料页修改姓名、手机号等字段，左侧资料气泡池应同步出现或更新气泡。
8. 设置岗位、城市、招聘类型、公司类型后，左侧气泡池应出现意向岗位、意向城市、招聘类型、公司偏好。
9. 完成检查页应展示简历资料、岗位偏好、自动填写策略汇总。
10. 点击“进入 KikiJob”后进入主页工作台。
11. 点击“智能推荐”后，推荐结果才出现。
12. 推荐结果应分为“推荐岗位”和“搜索推荐”两栏。
13. 搜索推荐按钮应显示“跳转搜索”；官网入口按钮应显示“官方投递”。
14. 新推荐岗位默认不应自动出现在“我的收藏”或“投递记录”。
15. 点击岗位卡片右上角爱心后，该岗位应进入“我的收藏”，状态为“收藏/待投”。
16. 再次点击爱心或取消收藏后，该岗位应回到“待确认”，不应从岗位池删除。
17. 进入辅助投递，选择已收藏岗位，应自动带出岗位链接。
18. 打开招聘官网后，用户应手动登录，系统不读取密码和验证码。
19. 插件扫描当前申请页后，KikiJob 应能导入扫描 JSON 并展示字段匹配结果。
20. 用户确认字段后，应能复制扩展填充包。
